# Gate 05 — leakage-safe entity split and label boundary

**Status: specification plus synthetic reference tests; not a Phase 2 execution.** No real rows were read into this workstream, no model was trained, and no real fold manifest/drop counts were computed. The primary worktree is read-only evidence; citations below refer to its Phase 1 report and inspected source.

## Frozen split contract

Use seed **20261010** and exactly **five outer folds**. Build each entity's platform-pattern stratum as its sorted set of distinct platform values. Within each stratum, sort entity identifiers, apply a deterministic pseudorandom shuffle keyed by seed and stratum, then assign round-robin fold numbers 0–4. Entity membership—not profile rows or pairs—is the split unit; all profiles of an entity inherit its single outer fold. This is approximate stratification by observed platform pattern, not exact proportional balancing: small/rare patterns can be unbalanced, entity size is not balanced, and the same entity's platform signature may not capture other covariates. Record per fold entities, profiles, and pattern counts; disclose empty/rare strata. A changed population changes assignments within strata and must produce a new manifest/hash.

For each outer run i∈{0,1,2,3,4}, assign fold i to TEST, fold (i+1) mod 5 to CALIBRATION, fold (i+2) mod 5 to POLICY_VALIDATION, and the remaining two folds to TRAIN. This is the specified rotation, not a secondary 70/15/15 entity hash split. Consequently role sizes are approximately 40/20/20/20 only when folds are sufficiently balanced. Role names in machine-readable artifacts should use the canonical values TRAIN, CALIBRATION, POLICY_VALIDATION, TEST.

## Pair eligibility and accounting

Create a complete profile-row-ID → entity → role lookup from the frozen manifest. For each unique candidate pair, require both endpoints to exist in the lookup. Retain iff `role(endpoint_a) == role(endpoint_b)`; otherwise drop as `cross_role_endpoint_pair`. Do not move endpoints or reassign a pair to the first endpoint's role. Count input unique pairs, eligible same-role pairs by role, dropped cross-role pairs, and invalid/unknown endpoint errors. Assert `input_pairs == same_role_pairs + cross_role_dropped`; assert no pair-key duplicates and that every retained row's two endpoint roles equal the row role. Apply the rule to every pair class and candidate source before labels are joined. Pair eligibility is not a substitute for entity-atomic splitting.

Every fit-able preprocessing object (vocabulary/TF-IDF, imputers, scalers, feature selection, learned embeddings, classifier) fits on TRAIN profiles/pairs only and transforms CALIBRATION, POLICY_VALIDATION, and TEST without refitting. Fit calibration only on CALIBRATION; choose policy only on POLICY_VALIDATION; freeze all choices before TEST prediction/evaluation. Feature computation that is a fixed label-free pairwise formula may transform any role; it must not fit corpus statistics across roles. The existing feature stage exposes a leakage warning: Phase 1 limitation report records historical TF-IDF fit across all profiles and requires TRAIN-only fitting. V2 runner source uses separate roles, but its inspected split helper uses nested hash percentages rather than this five-fold platform-pattern contract; do not conflate the two.

## TEST labels: code lifecycle vs security claim

TEST labels must be absent from candidate, feature, training, calibration, policy-validation, and prediction artifacts. Generate and freeze predictions (including pair keys and model/policy/config hashes) before the final label join. A programmatic store/guard should reject any TEST-label read except the explicitly named final evaluation phase, log denied/allowed attempts, reject label columns in public artifacts, validate one-to-one pair keys, and fail on missing or duplicate labels. The existing `real_adapters.py` and `label_sealing.py` implement lazy/phase-guarded reads; this demonstrates an application-level lifecycle control only. It does **not** establish external security: same-process code may inspect files/memory, users with filesystem access may open labels, logs/backups may leak them, and the corpus has been historically explored. Use filesystem/credential isolation and independent custody for a genuinely blinded evaluation; describe this design as programmatic TEST-label lifecycle, not an external holdout or never-seen corpus. Phase 1 explicitly warns that changing seed cannot make the explored corpus unseen.
